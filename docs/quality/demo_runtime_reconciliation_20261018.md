## 3. 确定的展示问题及未命中的执行风险

1. `trading_page.py` 的状态折叠先判断 trade_state=closed，将本次 3 个零成交撤单也归入“已平仓”。
   “已结束”不等于“成交后平仓”；protection_unknown 也没有被纳入“不确定”的状态分支。
2. `demo_store.py:projection_rows` 按 rowid 取成交，而 API 批次常按新到旧导入，当前 10 笔显示顺序已非时间倒序。
   独立离线探针使用真实查询，200→1 导入后选中 1–150，而正确最新应为 51–200。
   当前只有 10 笔，150 条截断遗漏尚未发生；不能把潜在截断说成当前漏成交。
3. orders 与 fills 的筛选不同：orders 按品种/状态、最多 30 行；fills 只按品种。
   费用按期间及账本起点。intents 先截 150，再排除无 request 的记录，后续还存在旧计划被 no_trade 挤出的风险。
   当前只有 54 intents，未命中该截断。
4. 当前缺少成交行到正式计划/测试计划及入场/退出的可见关联，用户无法直接对账。
5. 独立审查离线复现入场查询为空的执行缺口：snapshot 已有本单 fill 和净仓，entry GET 返回空时，
   observe 没有将 entry 标未知，manage 可因本地剩余量为 0 而不核对，投影仍可能 ready、无保护。
   这是需要优先修复的保护与披露风险，不是可接受的账户口径差异。
   **本次线上未发现该状态：当前仓位为 0，正式唯一成交已精确关联入场及退出，不能说它导致了本次两表差异。**

## 5. 判断与建议边界

- 对最新这笔，单纯由 3h 延到 6h/12h 不能解决；入场需要约 1.65% 反弹，结构锚点有依据，
  但模型没有充分说明短期为何可达。原 entry_reachability 仅说未来反弹可能触达、无保证。
- 当前 TTL/金额由 Host 冻结，不作为模型输入；结构选价和实际有效期分属不同契约。
  若今后让模型知晓有效期，属于明确的输入/身份契约变更，须设计、冻结并验证，不能临时读取实时设置。
- 最新 Entry/stop/TP1 为 82900.5/83072.8/80780，计划 RR 约 12.31；其主观概率明确属于限价成交条件下。
  它不代表 3h 内有同等成交概率，也不足以证明位置合理或错误。
- 唯一真实策略成交后很快止损；样本不足以判定方法失效，也不能用“多成交”当优化。
  应区分回到阻力后拒绝与强势穿越阻力，VPA/PA 可提供反证，未来确认不能伪装成普通限价自动条件。
- 优先修复未知入场的安全披露和两表状态/归属/时间排序，再用更多同版本自然样本比较当前入场、其他有依据位置与等待。
  不因本次样本直接加位置距离 Gate、改价、统一缩止损、延长现存订单，或引入 ICT。
- 3h 保持初始默认尚可；若研究 6h/12h，须独立对照并保留未成交、迟到、结构变化、成本和失败，不仅比较成交率。
- 分析失败需要独立排障，尤其 VPA 180s 预算停止及 repair 权限；它们会减少有效输出，与 TTL 撤单是不同链路。
