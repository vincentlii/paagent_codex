# ADR-0001：分析权限与失败契约

- 状态：Accepted
- 日期：2026-07-20

## 背景

近期运行暴露出两类系统性风险：一是程序与 LLM 同时解释市场语义，形成重复路由和事实冲突；
二是把格式差异、专业分歧与安全错误都当成硬失败，导致模型输出稍有变化便中断整次分析。

## 决策

采用“程序冻结事实，PA 提出假设，VPA 检验证据，联合裁决选择时机，程序执行安全”的单向数据流。

程序拥有事实与执行权限，LLM 拥有市场解释权限。PA、VPA 和联合裁决使用独立的结构化契约；
VPA 只能作用于已有 PA 候选，Brooks Router 仍是唯一策略路由。

验证结果分为三类：

- `hard_error`：事实矛盾、未知证据、越权、关键结构不可恢复、非法订单。
- `normalized`：无损格式修复、枚举别名、容器和引用记号规范化。
- `warning`：可选字段、措辞、事件标签不确定性等不影响安全的质量问题。

外部故障必须映射为明确 `RunOutcome`。VPA 与联合裁决失败时允许 PA-only 降级；PA 或输入失败时
只能返回不可用状态，不能保留半成品订单。

## 取舍

顺序调用增加了 Soft 模式的最小调用次数，但每一阶段职责更窄、上下文可复用，能降低 Prompt
重复和结构化失败。VPA 不再直接修改胜率，短期内少了一个主观调整通道，换来可校准性和更清晰的
因果归因。

## 后果

- 旧的双阶段兼容入口可暂时委托新服务，但不得保留独立决策逻辑。
- Schema 验证不能依赖自由文本正则来判断专业语义。
- 运行记录必须保存输入身份、阶段状态、证据引用和降级原因。
- 任何未来概率 Gate 都必须先通过样本外可靠性与 Brier score 校准。
