## 1. 目标与已确认范围

用户已选择 OKX 模拟盘，报告已创建专用 API，并要求进行下一步。目标是让已验证的正式
PA/VPA 联合分析产生可追踪的交易所模拟订单，成交、持仓和费用由 OKX 回报确认，解决本地
OHLC 无法确定柱内成交顺序的问题。模拟收益不等于实盘收益，也不证明策略有效。

用户随后明确采用固定名义金额：每笔订单总价值 500 USDT，不是保证金 500 USDT；
不按止损距离、权益百分比或模型置信度调整金额，不用杠杆把名义金额放大。
入场、结构止损、TP1 均保留已验证 PA Agent 原价；实际成交只能由交易所确认。

此前讨论的初版方向：保留 Binance 1h/4h 分析行情；先验收 BTC，再逐项启用 ETH、XAU；
分析链及模型权限不变；旧 Paper 历史单独保留。以下账户、风控与异常处置是具体设计建议，
用户尚未批准这些新增执行选择。API 的实际权限、IP 白名单和账户模式尚未通过私有接口验证。

本轮设计不修改四个既有 ICT 文件，不修改 AGENTS、Skills、Prompt、Router、原 Frozen Job
或模型概率，也不把 API 创建成功称为项目已经接通交易所。

## 3. 方案取舍

| 方案 | 优点 | 代价/结论 |
| --- | --- | --- |
| **独立 OKX Demo 执行进程，推荐** | 交易凭据与模型/分析进程隔离；暂停分析、模型超时不停止保护和对账。 | 增加一个 systemd 服务、专属状态目录及窄范围意图交接。 |
| 在 Headless 内直接调用 OKX | 进程和交接更少。 | 扩大 Host 的交易凭据权限，网络/恢复逻辑与分析轮询耦合，保护链更难隔离。 |

推荐首版使用现有 HTTP 客户端、独立持续 REST 对账，不引入通用多交易所框架、外部消息队列
或 SDK/WS 新依赖。独立执行循环不复用行情的 15 秒轮询；检测延迟如实计量，不声称即时保护。
WS 是后续降低检测延迟的可选改进，不能替代 REST 初始及重启对账。[S2]

## 4. 唯一执行路径与权限

数据流为：冻结分析 → 原 Validator/Risk/Trader Equation → record+audit 持久化 →
Host 生成带 digest 的不可变执行意图 → Demo 执行进程重新校验时效/账户风险 → OKX →
Demo 账本 → 脱敏 JSON → Headless 状态投影 → Dashboard。

- 新增显式正式执行选择 `paper | okx_demo`，默认仍为 paper；不跟随分析 Backend 或 API 文件存在自动启用。
- opt-in 切到 Demo 时停止生成新的正式 Paper 订单；旧活跃 Paper 订单仍由原 reader 观察至终态。
  旧账本、quarantine、v3/v4 和研究账户不迁移，不重新判定模糊订单。
- 每次切换保存 cutover ID、启用时间和第一项允许的新任务身份。已冻结/已开始/历史成功记录
  不能因切换自动补发。新 Snapshot 的任务在冻结时绑定执行代次；不改旧 Job 身份。
- 正式切换仅在分析暂停、Host/模型 Worker 排空且无恢复阻塞时进行。旧代次尚未提交的分析
  只记录 `skipped_cutover`，不新增 Paper 或改发 Demo；已经存在的 Paper 订单仍正常观察。
- 同一 task 与执行代次只能选择一个正式执行目标。切换与消费并发时以持久目标为准，
  不能先 Paper 再悄悄补一笔 Demo。未交付意图可由原 record 重建，但必须保持原身份和绝对期限。
- Headless 交接只写本地有界、原子落盘的意图文件。Worker 不读生产数据库、不改分析结果；
  在独立 SQLite 中登记消费、状态和回执，重启对账后决定是否可执行。重复文件不重复下单。
- 交接目录仅 Host 可写、Demo Worker 只读；`audit_ok` 与 record 持久化由 Host 原入口确认，
  并从同一已接受 record 编译意图。payload digest 检查交付完整性，record digest仅作来源锚；
  不能声称 Worker 未读原 record/审计库却独立证明了其审计状态。解析前限制文件大小/Schema。
- Worker 在专属状态目录写持久消费回执，不修改输入意图；Host 确认回执后才可清理已消费项。
  队列满显式阻断新交接并保留原 record，不淘汰未确认项；补交接不重跑模型。目录独立授予
  遍历/读取权限，不能为了共享文件让 Worker 遍历整个 PA_AGENT_HOME。
- Codex 用户不读意图目录、Demo 私有状态或 API 凭据；Dashboard 只读脱敏投影，不能下单、
  改风控、填 Key 或切实盘。Demo Worker 无 LLM 凭据和源码写权限。

交接由 `run_id/task_id`、pipeline、源 Snapshot/hash、冻结源规格、执行策略/代次、
record digest、原始候选和 effective disposition、交付时点/期限组成；不交付整份 Prompt/教材。
Worker 必须复核 digest、允许的正式协议和确定性订单资格，不独立解释自由文本或重做市场判断。
执行代次/账户/映射绑定不改变行情 `market_snapshot_hash`，也不把同一行情变成新独立样本。
有效 No Trade 也生成无 entry 的执行意图，不能因没有订单候选就丢掉旧挂单替代请求。

## 5. 账户与市场初值（待用户确认）

| 项目 | 首版建议 |
| --- | --- |
| 环境 | 仅 `okx_demo_v1`，模拟 Key，请求强制 `x-simulated-trading: 1`；无实盘选项。 |
| Demo 账户 | 使用专用于本项目的模拟交易账户；已创建主账户模拟 Key 可用，但同账户不能混用手工/其他程序订单。 |
| 模式 | 合约账户模式、单向 `net_mode`、逐仓；启动只读检查，不自动切换账户模式或覆盖未知仓位。 |
| 启用品种/类型 | 首次只开 BTC-USDT-SWAP 的普通 LIMIT；ETH/XAU 先实现显式映射，逐项验收后启用。 |
| 同品种 | 最多一项入场计划或持仓；不加仓、不对冲、不自动反向平仓开仓。 |
| 单笔金额（用户已定） | 固定目标订单总价值 500 USDT，非保证金；所有品种采用同一目标金额。 |
| 仓位计算 | 由原始限价、OKX 合约面值与数量步长计算张数并向下取整，不按止损距离/权益比例缩放，不超配后声称仍是固定金额。 |
| 风险记录 | 原止损对应的 USDT 计划损失仅作统计；撤销本提案的单笔1%、组合3%及10,000 USDT风险资本初值，不沿用为隐性缩量或新Gate。余额/保证金、合约约束及原正式执行资格仍须满足。 |
| 逐仓杠杆 | 暂保留建议 3 倍并只读核对；它只影响所需保证金，不把 500 USDT 变成 1,500 USDT。模式/杠杆不符时不自动更改。 |
| 退出（用户已定） | 精确使用原结构 stop 与 TP1，TP1 全量退出；无 TP2、移动止损、补仓或模型持仓管理。 |

单向模式下，一笔新有效分析可以撤销旧未成交余量；已经成交的部分保留原结构退出。已有仓位
时新交易候选标记 `position_exists`，不能因为分析换方向把它当作平仓授权。
来源不明的持仓/订单或账户模式冲突阻止新入场，不能自动接管、撤销或清仓。

固定金额公式（仅正向 USDT 永续）：每张名义价值 = 原限价 × `ctVal × ctMult`；
目标张数 = `floor(500 / 每张名义价值 / lotSz) × lotSz`。实际提交名义金额不得大于 500 USDT，
原 stop/TP1 不参与计算张数；不能为了满足最低下单量向上加到 500 USDT 以上。
取整后的数量低于最低要求、超过订单数量限制或可用保证金不足时整单拒绝，不自动换金额。
保存目标 500、实际计划名义金额、张数和取整差额。实际成交金额可能因更优价格或部分成交
小于计划金额；手续费/资金费另计。不得为凑足 500 追单、补单或改变退出价。

## 6. Binance 分析与 OKX 执行身份

显式绑定 BTCUSDT → BTC-USDT-SWAP、ETHUSDT → ETH-USDT-SWAP、XAUUSDT → XAU-USDT-SWAP；
绑定还包含分析 source/venue/instrument_type、执行 venue/environment/account/settleCcy、
映射版本及批准时间。不得只用字符串替换；XAUT/PAXG 不替代 XAU。

先用冻结的 Binance InstrumentSpec 验证原分析身份与资格，再独立绑定 OKX Demo 的实时合约
约束；保存两套规格及观察时间，不能用目标规格替换原 Snapshot 或从源规格推测目标数量。
价格和张数运算使用 Decimal；按固定名义金额公式计算，避免用二进制 float 判断是否合法 tick。

- 原始 entry/stop/TP1 不变；若不能精确符合 OKX tick，拒绝并给出 `target_tick_mismatch`，不自动四舍五入或平移价差。
- 合法普通限价允许成交或挂单，不擅自改成 post_only；新鲜目标报价仅用于明确的几何、
  可执行风险和已失效条件检查，不新增“离支撑太远”等主观 Gate。
- 首版市价/突破候选处置为 `unsupported_order_type`，保留原分析，不改成限价或立即市价。
  完成限价全生命周期后才另行审阅这些类型的入场价格界限/保护协议，不在本轮偷偷补功能。
- 普通 LIMIT 的原价限定最坏入场价；固定金额决定张数，原 stop 用来统计计划损失，
  不反向决定张数。核对实际可用保证金并保存报价/观察时间，不使用 Paper 滑点假设代替成交事实。
  止损市价退出仍可能跳空，计划损失不是保证值。
- 不以本轮设计新增任意跨所基差阈值。记录分析价与执行报价/时间，报告标明跨所执行，
  不据此归因 PA/VPA 收益。若频繁 tick/产品不兼容，再单独审阅是否改用 OKX 分析行情。

## 7. 执行状态、幂等及对账

同一账户由单个执行进程串行预约资金，同品种单飞。先在本地事务持久化意图、资金占用、
完整请求语义摘要及预生成客户 ID，再发网络请求；数据库唯一约束防止两个 Worker 或重复恢复
重复释放。不能跨网络持有 SQLite 写锁或把网络成功等同本地事务原子提交。
资金与风险统计按同一交易的已成交量加未成交余量核算，不把整笔预约与已成交占用再加一次；
未知请求保留预约，撤销/平仓以对账确认后释放。无法解释的同账户外部敞口阻止全部新入场。

客户 ID 根据 environment/account/cutover/task/leg 派生，符合 OKX 格式；分开保存 entry clOrdId、
保护/触发 algoClOrdId、真实 ordId/algoId、触发后子订单和 tradeId。交易所客户 ID 的唯一性
不能代替本地永久幂等记录。[S2]

意图处置与订单状态分开：`no_trade/rejected/queued`、`submitting/submission_unknown`、
`live/partially_filled/filled/cancel_pending/canceled`，另有
`protection_pending/protected/protection_failed/reconciling/closed`。不能用一个 status 同时描述
“已成交”和“保护失败”。保存状态观察时间、累计成交量/均价及账户对账水位；重复或乱序信息
不减小累计成交量、不把终态回退成 live。

下单超时、5xx、响应无法解析或进程在请求后崩溃，先按固定客户 ID、未完成/历史订单、成交和
持仓对账。没有查到一次不代表没有下单；证据不足保持 unknown、保留风险占用并阻止再次开仓。
首版对未知提交不自动重发。明确的可重试且确认未执行的拒绝才可在原有效期限内有界重试。
HTTP 成功和单条业务 sCode 必须分别检查；撤单回执也不等于撤单完成。[S2]

启动先取得账户配置、资金、全部相关普通订单/条件单、持仓及有分页覆盖的成交/账单，
与本地逐项核对。恢复对账完成后才接受新入场；达到交易所历史保留边界仍无法解释的间隙
保持 `reconciliation_gap`，不补造历史/零费用/零收益，也不重新调用模型。

## 8. 部分成交、保护及断线

首版以独立执行循环持续 REST 查询作为真实状态来源，活跃订单/持仓目标查询周期 2 秒，
无活跃状态时降低频率；所有请求有超时/限流退避。记录真实查询间隔，2 秒不是保障或 SLA。
网络异常或快照过期暂停新入场，撤单/保护/退出/恢复继续。分析 Pause 也不停止管理已有单。

**保护必须覆盖部分成交。** 不只依赖父单附带 TP/SL，也不等父单全成交后才处理。[S1]
首次发现部分成交，先为已知净仓建立或核实服务器端保护，再撤销未成交余量，并对账取得最终
成交量；首版不反复追求补满原计划数量。撤单期间新成交继续纳入同一交易，不能视为全撤成功。

首选独立、只减仓、net 全仓位退出 OCO：`closeFraction=1`、原 stop/TP1、last 触发、
触发后市价退出。必须在受控 Demo 验收证明该账户/品种支持并实际覆盖部分成交后的仓位；
不支持则拒绝开放该品种自然入场，不能静默切另一种未验收保护路径。普通 conditional 同时
填 TP/SL 不能冒充有效双边 OCO。[S3/S4]

止盈/止损设置值必须与已接受 PA Agent 的 stop/TP1 逐值相同；不按实际入场均价移动，
不改成百分比、ATR、保本价或更近的价格。无法合法设置原价时标记执行失败，而非创造替代价。
触发价格严格相同不等于成交价保证相同，退出按实际回报记账。

保护创建/查询超时必须先查现有 algo，不能盲建重复保护。若无法建立/确认有效保护：标记
`protection_failed`、撤余量、对已确认仓位尝试 reduce-only 市价平仓，并阻止该市场新单；
平仓也可能失败或超时，持续查询和保留未知状态，发本地告警/状态，不称“已安全退出”。
即使认为平仓成功，也须对账到入场父单终态、仓位零、无潜在迟到入场/旧保护后才能解除阻塞。

服务器保护只能在创建成功后提供执行条件；从成交到发现/保护、网络故障与触发失败仍有窗口。
不保证原子 bracket、精确止损价或零裸仓时间。账户不能混入其他持仓，否则 close-all 归属不成立。
保护触发后的实际子订单、成交、费用须对账；`algo effective` 不直接等同平仓成交。
保护一旦触发，立即撤父入场余量并核对终态。若OCO已经消耗后父单又有竞态成交，视为同一
交易新增的未保护暴露，重新保护或进入故障平仓；不能因曾经观测到仓位零就忽略迟到成交。
父入场单未终态、仓位未归零或保护残留未对账时，交易不能记为 closed、释放全部风险或接受新单。

## 9. 时效、新分析替代及进程停止

继承已有冻结语义：结果必须在下一主周期收盘前被接收；带 limit_3bar_v1 的 1h 限价挂单
最多至 K1 open+4h，即分析所用 K1 收盘后第三个后续收盘。market/breakout 首版不执行、原时效不改；交付、
重启、查询失败不续期。入场请求的 `expTime` 只限定请求处理期限，不冒充挂单 TTL。[S1]

绝对到期由独立执行循环发起撤余量，真实状态直到交易所确认才变化；过期后收到迟到成交仍
是成交事实，需要保护/退出及 `late_fill` 审计，不能删除该笔成交。服务离线期间不承诺准点撤单。
新有效分析（含 No Trade）先对旧计划发撤单并确认最终成交/仓位，再决定新单；无效/失败分析
不撤旧计划、不续期。已经成交的仓位保留其原退出逻辑，No Trade 不自动平仓。
每个源身份+目标品种+周期保存已接受决策的K1时间水位；旧No Trade/候选乱序到达时记录
`stale_decision`，不得撤掉更新计划。相同 task 重投递仍走幂等，不把水位当新的入场授权。

新增独立执行入场开关；默认禁止入场。关闭/进程退出前停止新入场、撤尚未成交余量并核对，
保留服务器端保护；保护/对账服务的停服和升级不跟随模型 Worker 自动进行。
Headless Pause 生效后不释放新的可开仓意图；已有交易所挂单继续按原期限管理。Demo Worker
只在控制状态新鲜、入场开关开启时启动新的 entry；旧保护和平仓不被 Pause 取消。

不使用账户级 cancel-all-after 代替单笔到期，避免把保护单或别的项目订单一并撤掉。

## 10. 凭据、数据及展示

- 凭据仅在 VPS 专用 root 管理的 secret 文件/systemd credential 中保存，独立执行用户只读；
  配置、Prompt、Git、SQLite事件、日志、浏览器截图及普通备份不含 Secret/Passphrase/签名。
  当前未读取用户网页 API 详情或凭据。创建 Key 不授权把它通过聊天或任意渠道复制到 VPS。
- 固定官方区域 REST 域名及 TLS 校验；每次签名请求强制模拟标记，禁止凭配置切到实盘、
  跟随重定向泄露签名或在错误/认证失败后切实盘。预检核对账户、权限、白名单和时钟。
- 新 Demo 状态/SQLite 默认位于 PA_AGENT_HOME 派生的 execution 目录；部署显式设置独立
  `PA_AGENT_EXECUTION_HOME=/var/lib/pa-agent-execution`，避免为交接授予 Worker 遍历生产状态根目录的权限。不迁移三份现库。
  凭据与普通 settings 分离；只有显式非敏感的配置进入 manifest/投影。
- 原子发布 `exchange_demo` JSON，包括资金/风险、候选处置、普通/条件单、持仓、保护状态、
  实际成交/手续费/资金费和数据覆盖。事件保留 exchange time 与本地 observed time。
- 成交以账户+品种+tradeId 去重，账单以 billId 去重；平仓盈亏与手续费/资金费分开核算，
  不把 position realizedPnl 再叠加已含的费用。缺失账单不计零，标记未对账。
- 启用 OKX Demo 后，交易概览默认及主视图改用 Demo 资金/权益、持仓、订单、成交、
  实际费用/资金费、已实现及浮动盈亏，明确“OKX 模拟盘”。期间净收益曲线基于可对账的
  Demo 账单，充值/重置余额等外部资金流不得当盈利；分析次数/复盘仍来自原分析记录。
- Demo 断线、过期或未完成对账时保留最后数据并标记状态；不自动回退显示 Paper 或把未知计零。
  行情报价、Worker/账户数据新鲜度与Host心跳分别判断；不能因Host在线就声称账户实时。
- 旧 Paper 以明确的历史选择保留 v3/v4，主视图不混入其订单、余额或收益。普通未启用 Demo
  配置继续原 Paper 页面；不是删除旧功能。交易页仍不持有凭据，不直接请求 OKX 或打开DB。
- 新流水与 Paper/真实执行分开，保持分析 run_id 关联。`analysis_outcomes` 和
  `counterfactual_outcomes` 不自动写入模拟成交；Demo 净收益不加入旧 Paper 曲线或样本。
- 后续部署前先停止 Demo 写入并对新库做一致性备份/quick_check，manifest 不含凭据。
  代码回退不得让旧 Paper 自动接管 Demo 活跃单；即使禁新入场，兼容的保护/对账进程仍需运行。

## 12. 设计审查与剩余决策

已完成一次只读协作者及主审的 PA/VPA/架构核对：方向不重写 Setup/概率；VPA不获得执行
权限；新增限制只作用账户执行及可复算身份，不变成模型专业判断 Gate。最初多订单直接映射
net 的方案已放弃；本版采用每品种单计划/持仓，未知状态及保护失败都不掩盖。

用户已明确单笔名义金额500 USDT及原建议止盈止损；此前的按权益/结构止损定仓方案已被此修订替代。
其余待审选择：独立 Demo 进程、继续 Binance 分析的双身份、net+逐仓及不加仓、建议3倍逐仓
杠杆但不放大500名义金额、保护失败撤余量+尽力平仓、正式切换后不新增 Paper。
故障紧急平仓属于保护无法确认时的异常处置，单独记录而非声称触发了原止损；该处置仍待用户审阅，
不从“严格按建议设置价格”推导出已经批准其他主动策略退出。
首版只执行普通限价，市价/突破明确不支持；没有隐含的滑点参数或无界市价入场。
